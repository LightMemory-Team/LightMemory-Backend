# 計分標準化改版 — 變更說明（10/27）

> 本文件說明分支 `feat/score_standardization` 做了什麼、為什麼、前後端各要配合什麼，並整理「儀表板」與「週報表」目前完成的全部內容。
>
> 演算法細節見 [`game_scoring_algorithms.md`](game_scoring_algorithms.md)；週報 API 規格見 [`weekly_report.md`](weekly_report.md)。
>
> 用語原則：本 App 定位為「輔助維持認知活躍度」，所有分數只跟**自己**比，不作任何診斷用途。

---

## 一、為什麼要改

| 問題 | 原因 | 結果 |
|---|---|---|
| 六個維度的分數波動不一致 | 各維度合成的指標數從 1 到 5 個不等，指標越多平均後波動越小 | 整理菜籃、日記幾乎拿不到 90 分，冰箱檢查約 5.7%；雷達圖形狀反映的是「指標數量」，不是能力 |
| 冷啟動基準不穩 | 3 場的標準差很不穩；借全體資料時用錯變異來源（個人**之間**，不是個人**內**）；第一場有練習效應 | 新使用者前幾場的分數失真 |
| 解鎖太嚴 | 6 個維度全部滿 3 筆才整包解鎖 | 只玩一款遊戲的人，雷達圖完全看不到 |

規格依據：《憶智防線 認知維度計分規格：標準化與冷啟動》（10/27）。

## 二、解法（三條規則）

1. **先 z 再加權，一律等權重**：每個指標先各自換成 z，再平均（Dawes 1979，等權重通常不輸調出來的權重）
2. **二階段標準化**：合成分數再除以「合成分數自己的標準差」，不管 1 個還是 5 個指標，最後的 z 標準差都接近 1
3. **收縮估計＋熟悉場**：
   - 基準 = 「自己」與「全體」依場次數加權，自己的場次越多越偏向自己（收縮強度 k = 3，`PRIOR_STRENGTH`）
   - 全體的變異用「個人內」變異（同一人多場之間的變化）
   - **每款遊戲的第一場是熟悉場**：不算分、不進任何歷史

驗證：測試用 200 場模擬，1 個指標與 5 個指標的最終 z 標準差差距 < 0.15（`games/tests_zscore.py`）。

## 三、計算算法

> 以下是六個維度共用的算法（程式：`games/zscore.py`）。各遊戲的指標細節與更多範例見 [`game_scoring_algorithms.md`](game_scoring_algorithms.md) 第 3～8 節。

### 1. 整體流程（每一場、每一篇日記都走同一條路）

```
① 取歷史      自己更早的有效場次（排除熟悉場）＋其他使用者的有效場次（依使用者分組）
② 算基準      每個指標各算一組「收縮基準」（平均、標準差）
③ 指標轉 z    z = (本場 − 基準平均) ÷ 基準標準差；越低越好的指標乘 −1；限制在 [−2, +2]
④ 等權重合成  合成分數 = 各指標 z 的平均（這場沒資料的指標跳過，剩下的權重按比例放大）
⑤ 二階段標準化 最終 z = 合成分數 ÷ 合成分數的標準差；限制在 [−2, +2]
⑥ 換算分數    分數 = round(50 + 25 × 最終 z)，限制在 1～100
```

任何一步缺資料（沒有基準、全部指標都無資料）→ 回傳 `null`，前端顯示「資料不足」，不顯示 0 或假分數。

| 最終 z | −2 | −1 | 0 | +1 | +2 |
|---|---|---|---|---|---|
| 分數 | 1 | 25 | 50 | 75 | 100 |

### 2. 步驟②：收縮基準（解決冷啟動）

```
平均   μ̂  = (n × 自己的平均 + k × 全體平均) ÷ (n + k)
變異數 σ̂² = ((n − 1) × 自己的變異數 + k × 全體個人內變異數) ÷ ((n − 1) + k)
標準差 σ̂  = √σ̂²
```

| 符號 | 意思 | 設定 |
|---|---|---|
| n | 這位使用者在這款遊戲（同一階段）的有效歷史場次，不含熟悉場、不含這一場 | – |
| k（`PRIOR_STRENGTH`） | 先借幾場全體資料 | 3 |
| 全體平均 | 其他使用者所有有效場次的平均 | – |
| 全體個人內變異數 | 每位使用者自己場次的變異數，依（場次 − 1）加權合併 | – |

- 自己占的比例 = n ÷ (n + k)，即 API 的 `personal_weight`：n = 0 → 0、n = 3 → 0.5、n = 9 → 0.75
- **為什麼用「個人內」變異數**：直接算全體標準差是「人跟人的差異」，通常比「同一人每次的波動」大，借來比會把 z 壓扁；等切到自己的歷史時分數才突然擺動
- 全體的個人內自由度（Σ(場次 − 1)）不滿 3 → 全體基準算不出來，退回只用自己；自己也不滿 3 場 → 這個指標無資料

| 情況 | 基準 |
|---|---|
| 自己 0 場、全體夠 | 完全用全體（熟悉場之後第一場就有 z） |
| 自己 n 場、全體夠 | 自己占 n ÷ (n + 3)，全體占其餘 |
| 全體不夠 | 只用自己，滿 3 場才算得出 |
| 歷史每場數值都一樣（標準差 0） | 全體個人內變異數有值就能算；全體也是 0 → 無資料 |

### 3. 步驟④⑤：等權重與二階段標準化（解決指標數量不同）

**問題**：N 個互不相關的 z 取平均，標準差是 1 ÷ √N。指標越多，合成分數越擠在 0 附近，分數就越難拿到高分或低分。

**解法**：合成後再除以合成分數自己的標準差。

```
最終 z = clamp( 合成分數 ÷ σ̂_C , −2, +2 )
σ̂_C² = ((n − 1) × 參考場次合成分數的變異數 + k × 理論變異數) ÷ ((n − 1) + k)
理論變異數 = Σ（正規化後有效權重²）
```

- **理論變異數**：指標互不相關時的值，不用資料就能算。等權重時 N 個指標 = N × (1/N)² = 1/N
- **參考場次**：自己過去的場次，用「這一場同一組基準」算出各場的合成分數（不能每場用各自當時的基準，尺度會不一致）
- 這一場少了某個指標時，參考場次也只用同一組指標合成
- **分階段的遊戲**：有效權重 = 階段權重 × 階段內指標權重；參考場次依各自最高到達的階段套權重
- 等權重依據 Dawes (1979)；複合變異數公式依 Nunnally & Bernstein (1994)
- 驗收：1 個與 5 個指標各模擬 200 場，最終 z 的標準差差距 < 0.15

### 4. 六個維度各自的指標

所有指標權重一律相等。

| 維度（遊戲） | 指標 | 方向 | 分階段 |
|---|---|---|---|
| 注意力（菜市場找路） | 正確率、平均反應時間、收斂曝光時間 | 高、低、低 | ✅ 每階段 3 個 |
| 工作記憶（煮菜過程） | 正確率、平均反應時間 | 高、低 | ✅ 每階段 2 個 |
| 執行功能（整理菜籃） | 整體正確率、switch 正確率、切換成本 RT、學習速度 | 高、高、低、低 | ❌ 4 個 |
| 視覺空間（冰箱檢查） | 正確率、速度分 | 高、高 | ❌ 2 個 |
| 數學（市場買菜） | 一次答對率、速度分 | 高、高 | ❌ 2 個 |
| 語言（聲影日記） | 流暢度、資訊量、句子組織、命名、語意（各 0～4 分） | 皆高 | ❌ 5 個 |

**分階段遊戲的跨階段權重**（菜市場找路、煮菜過程）：每階段先各自算階段分數，再依「這場最高到達的階段」加權：

| 這場最高到達 | basic | intermediate | advanced |
|---|---|---|---|
| basic | 1.0 | – | – |
| intermediate | 0.3 | 0.7 | – |
| advanced | 0.2 | 0.3 | 0.5 |

基準只跟「同一階段」比；階段分數 = 該階段各指標 z 的平均；合成分數 = Σ（階段權重 × 階段分數），只計入有資料的階段。

**特殊規則**

- 冰箱檢查、市場買菜：沒有反應時間資料時，速度分不列入，只剩正確率（單一指標的 z 就是最終 z）
- 整理菜籃：切換成本 RT 要 repeat、switch 題各答對 3 題以上才計算，否則跳過；整場沒有 switch／repeat 題或題數不足 28 題回傳 HTTP 400
- 不用「原始總分」算 z：原始分已含難度係數、加成與扣分，會把「升階比較快」誤當成進步；z 一律用原始指標

### 5. 熟悉場與全體資料範圍

- **熟悉場**：每位使用者每款遊戲的第一場，不算分（z、分數為 `null`），也不進任何歷史。玩到一半放棄的不算「玩過」。日記沒有熟悉場。
- **全體資料**排除：本人（本人是個人歷史）、熟悉場、`is_staff` 測試帳號、demo 種子資料（場次 `client_session_id` 以 `seed-` 開頭、日記 `audio_path` 以 `seed/` 開頭）；分階段遊戲只用同一階段
- **只比更早的**：歷史只取比這場更早結束（日記是更早建立）的場次，所以不管什麼時候算，同一場的結果都一樣

### 6. 計算範例：冰箱檢查

自己有 3 場歷史（正確率, 速度分）= (60, 70)、(70, 60)、(80, 80)，沒有其他使用者資料，所以基準就是自己的。

```
兩個指標的基準都是 平均 70、標準差 10
三場歷史的 z 是 (−1, 0)、(0, −1)、(+1, +1)
→ 合成分數 −0.5、−0.5、+1 → 變異數和 1.5（n = 3，自由度 2）
理論變異數（2 個指標等權重）= 2 × (1/2)² = 0.5
收縮後 σ̂_C² = (1.5 + 3 × 0.5) ÷ (2 + 3) = 0.6

這場 正確率 80、速度分 76
z_正確率 = (80 − 70) ÷ 10 = +1
z_速度分 = (76 − 70) ÷ 10 = +0.6
合成分數 = (1 + 0.6) ÷ 2 = 0.8
最終 z = 0.8 ÷ √0.6 ≈ 1.033
分數 = round(50 + 25 × 1.033) = 76
```

### 7. 儀表板與週報表怎麼用這些 z

| | 儀表板 | 週報表 |
|---|---|---|
| 取哪些 z | 近三個月（90 天）結束場次（日記為建立時間）的 z | 報告週與前一週各自的 z |
| 平均 | 各維度 z 平均 | 同左 |
| 換算 | `score = round(50 + 25 × z̄)`，限制 1～100 | 同左 |
| 解鎖 | 累計有 z 的場次（篇）≥ 3 | 同左，但算到「報告週結束」為止 |
| 整體 | 機器人卡片：每週整體分數以 0.8^週數 加權平均（越近越重），6 維度都解鎖才有 | 已解鎖且有分數的維度取平均 |
| 趨勢 | 近兩個有資料的週的總體分數差 | 本週 − 上週；差 ≥ +3 `up`、≤ −3 `practice`、其餘 `steady` |

| 遊戲 | 變更 |
|---|---|

### 4. 聲影日記語言 z（`dashboard/diary_zscore.py`）

5 個小分數改為等權重（不再綁 `diary/analysis.py` 的 `communication_score` 權重），套用收縮基準與二階段標準化；日記沒有熟悉場。

### 5. 舊資料重算指令

```bash
python manage.py recompute_scores --dry-run   # 先看會改什麼（transaction 內算完 rollback）
python manage.py recompute_scores             # 正式重算
```

- 回填熟悉場：每人每款遊戲「最早結束」的場次標記為熟悉場
- 依新算法重算每場的 `z_score` 與 1～100 分數，寫回 `result`（JSON 欄位）
- demo 種子場次不重算；可重複執行，結果只跟資料有關

{
  "success": true,

| `sessions_to_unlock` | 還差幾次，已解鎖為 0 |

**與舊版的差異（前端會壞的地方）**

**機器人卡片 `encouragement`**：6 個維度都解鎖才有值，否則 `null`。

| 煮菜過程 | `start` 回應（原本就有） | `total_score`、`z_score` |

非熟悉場但資料還不夠算的場次，分數也可能是 `null`：一律「有值才顯示」，不要只靠 `is_pretest`。

### 2. 儀表板與週報表

見第五、六節：改成讀 `unlocked`／`sessions_to_unlock`、處理 `score`／`encouragement`／週報分數為 `null`。

### 3. 分數數值會變

欄位名稱不變、範圍仍是 1～100，但同一個人的分數會跟以前不同；前端寫死的測試資料與截圖需重新取得。

### 4. 驗收順序

1. 全新帳號玩任一款第一場：結算畫面不壞，有熟悉場提示
2. 同一款再玩 2 場：`valid_count` 到 3，該軸變彩色
3. 只玩一款的帳號：其他 5 軸灰色、`encouragement` 為 `null`
4. 6 個維度都滿 3 次：機器人卡片出現
5. 週報：未解鎖的能力顯示解鎖提示，已解鎖的正常顯示
