## 1. 名詞說明

| 名詞 | 意思 | 例子 |
|---|---|---|
| **標準差** | 一組數字平常會上下晃動多少 | 正確率 0.6、0.8、1.0 → 平均 0.8，標準差 0.2 |
| **z-score** | 這次的表現離基準有「幾個標準差」遠 | z = 0 跟基準一樣；z = +1 比基準好 1 個標準差 |
| **比較基準** | 拿來比的「平均、標準差」，目前一律用自己過去的場次算 | 過去 3 場正確率 0.6、0.8、1.0 → 平均 0.8、標準差 0.2 |
| **50 + 25z** | 把 z 換成長者、家屬看得懂的 1～100 分 | z = +1 → 75 分；z = −1 → 25 分 |

```
z = (這次的值 − 基準平均) ÷ 基準標準差
越低越好的指標（例如反應時間）要乘 −1，讓所有 z 都是「越高越好」
```

`50 + 25z` 搭配「z 限制在 ±2」使用時，分數落在 **1～100**（z = −2 算出 0，最低給 1 分）：

| z | −2 | −1 | 0 | +1 | +2 |
|---|---|---|---|---|---|
| 50 + 25z（最低 1） | 1 | 25 | 50 | 75 | 100 |

- **所有 z 換算的分數都用這個**（10/26 統一）：煮菜過程 `total_score`、整理菜籃 `cognitive_flexibility_score`、冰箱檢查與市場買菜 `standard_score`、週報表的能力分數。z 是 `null` 時分數也是 `null`
- 程式：`games/zscore.py` 的 `z_score_to_display_score`
- 10/26 以前整理菜籃、冰箱檢查、市場買菜用 50 + 20z（10～90），舊場次存的分數不會重算

> 程式用的是**樣本標準差**（除以 n−1，Python 的 `statistics.stdev`）。

## 3. 菜市場找路 market_route

雷達圖維度：**注意力**

### 3-1. 原始總分 `total_score`

程式：`games/market_route/market_score.py`

```
單次作答得分 = round(基礎分 × 難度係數) + 速度加成
單場總分     = 所有作答得分加總（答錯、超時為 0 分，不倒扣）
```

| 第幾次答對 | 基礎分 | | 階段 | 難度係數 |
|---|---|---|---|---|
| 第 1 次 | 10 | | basic | × 1.0 |
| 第 2 次 | 6 | | intermediate | × 1.3 |
| 第 3 次 | 3 | | advanced | × 1.6 |

- **速度加成**：答對且反應時間 ≤ 曝光時間 × 50% → **+2 分**
- **理論最高 333 分**：每場固定從 basic 開始，最快連續 3 題快速答對就升階
  - basic 3 題 × 12 + intermediate 3 題 × 15 + advanced 14 題 × 18 = 36 + 45 + 252 = 333

**結束畫面的 `total_score` 換算成 1～100**（`normalize_total_score`）：

```
total_score = round(原始總分 ÷ 333 × 100)，限制在 1～100（全錯也給 1 分）
```

| 原始總分 | 0 | 12 | 166 | 333 |
|---|---|---|---|---|
| `total_score` | 1 | 4 | 50 | 100 |

> 每題的 `score_earned`（作答當下的即時回饋）仍是原始分數，沒有換算。

### 3-2. z-score（注意力分數）

程式：`games/market_route/market_zscore.py` 的 `calculate_attention_z_score(session_id)`

> **不用 `total_score` 算 z**：總分乘了難度係數，升到高階的場次天生分數就高，分不出是「真的進步」還是「升階比較快」。

**第一步：每個階段各算 3 個指標**（只看每題的第 1 次作答）

| 指標 | 定義 | 方向 |
|---|---|---|
| 正確率 | 第 1 次就答對的題數 ÷ 該階段題數 | 越高越好 |
| 平均反應時間 | 第 1 次作答、非超時的反應時間平均 | 越低越好 |
| 收斂曝光時間 | 該階段最後一題的曝光時間 | 越低越好 |

**第二步：跟自己過去「同一階段」的歷史比**

```
z_正確率   =      (本場 − 歷史平均) ÷ 歷史標準差
z_反應時間 = −1 × (本場 − 歷史平均) ÷ 歷史標準差
z_曝光時間 = −1 × (本場 − 歷史平均) ÷ 歷史標準差
每個 z 都限制在 [−2, +2]
```

**第三步：階段內加權**

```
階段分數 = 0.4 × z_正確率 + 0.3 × z_反應時間 + 0.3 × z_曝光時間
```

**第四步：依這場最高到達的階段，跨階段加權**

| 這場最高到達 | basic | intermediate | advanced |
|---|---|---|---|
| basic | 1.0 | – | – |
| intermediate | 0.3 | 0.7 | – |
| advanced | 0.2 | 0.3 | 0.5 |

```
注意力 z = Σ（階段權重 × 階段分數），只計入有資料的階段
```

**範例**：歷史 3 場、這場到 intermediate

```
basic：        z_正確率 +1.0、z_反應時間 +0.5、z_曝光 0   → 階段分數 0.55
intermediate： z_正確率 0、  z_反應時間 +1.0、z_曝光 +2.0 → 階段分數 0.9
注意力 z = 0.3 × 0.55 + 0.7 × 0.9 ≈ 0.80
```

- 每個指標都在 ±2 內，所以加權後的注意力 z 也一定在 ±2 內
- **結算（`finish/`）時算好**，四捨五入到小數 3 位，存入 `result.z_score` 並回傳；歷史不足時是 `null`
- 結算時這場還沒有 `finished_at`，會跟「所有已結束場次」比，結果跟之後再算一樣

冷啟動、資料不足的處理見第 8 節。

## 4. 煮菜過程 memory_recall

雷達圖維度：**工作記憶**

### 4-1. 每輪得分 `score_earned` 與結束畫面 `total_score`

程式：`games/memory_recall/score.py`

**每輪得分**（作答當下的即時回饋，沒有改）：

```
單輪得分 = round(10 × 難度係數)，答錯 0 分
```

| 階段 | 答對得分 |
|---|---|
| basic | 10 |
| intermediate | 13 |
| advanced | 16 |

- **不加速度分**：計時制下，反應快的人自然能答更多輪

**結束畫面的 `total_score`**（`games/zscore.py` 的 `z_score_to_display_score`）：

原始分數加總**沒有固定上限**（一場最長 90 秒，答得越快輪數越多），沒辦法等比例換成 1～100，所以改用本場的工作記憶 z（見 4-2）換算：

```
total_score = round(50 + 25 × 工作記憶 z)，限制在 1～100
```

| 工作記憶 z | −2 | −1 | 0 | +1 | +2 | `null` |
|---|---|---|---|---|---|---|
| `total_score` | 1 | 25 | 50 | 75 | 100 | `null` |

- **前測**、**歷史不足算不出 z**：`total_score` 為 `null`，前端顯示提示文字
- 舊的「單場總分 = 所有答對輪得分加總」不再回傳；`calculate_total_score` 函式保留但結算沒有使用
- 舊的 X-score（`normalize_to_100`）已刪除

### 4-2. z-score（工作記憶分數）

程式：`games/memory_recall/memory_zscore.py` 的 `calculate_working_memory_z_score(session_id)`

比照菜市場找路的四步驟，差別如下：

| | 菜市場找路 | 煮菜過程 |
|---|---|---|
| 每階段指標 | 正確率、反應時間、收斂曝光時間 | **正確率、反應時間** |
| 階段內權重 | 0.4／0.3／0.3 | **0.5／0.5** |
| 只看第 1 次作答 | 是（可以重看） | 不需要（每輪只答一次） |
| 前測 | 沒有前測 | 前測那場**本身回傳 `None`**，但會被當成之後場次的**歷史基準** |

```
階段分數   = 0.5 × z_正確率 + 0.5 × z_反應時間
工作記憶 z = Σ（階段權重 × 階段分數），跨階段權重同菜市場找路
```

**範例**：歷史 basic 正確率 0.5／0.6／0.7、反應時間 1200／1100／1000 ms，這場正確率 0.8、反應時間 1050 ms

```
z_正確率   = (0.8 − 0.6) ÷ 0.1          = +2.0
z_反應時間 = −1 × (1050 − 1100) ÷ 100   = +0.5
工作記憶 z = 0.5 × 2.0 + 0.5 × 0.5      = 1.25
total_score = round(50 + 25 × 1.25)    = 81
```

- 每個指標的 z 限制在 ±2，同菜市場找路
- **結算時算好**，存入 `result.z_score` 並回傳；單輪超時自動結束的場次也一樣

## 5. 整理菜籃 market_sort

雷達圖維度：**執行功能（認知彈性）**

程式：`games/market_sort/services.py` 的 `calculate_cognitive_flexibility_score(questions)`

> 玩完一場後，前端一次把 28 題的資料送到後端。**對錯、題目類型（repeat／switch）由前端判斷**。

### 5-1. 4 個指標

程式：`METRIC_RULES = {指標: (權重, 是否越低越好)}`

| 指標 | 定義 | 方向 | 權重 |
|---|---|---|---|
| 整體正確率 | 28 題答對比例 | 越高越好 | **0.40** |
| switch 正確率 | 規則剛換的題目答對比例（第 1 題不算） | 越高越好 | 0.25 |
| 切換成本 RT | switch 題平均 RT − repeat 題平均 RT（秒，只算答對的題） | 越低越好 | 0.20 |
| 學習速度 | 規則改變後（第 5、10、15 題後），要幾題才追上新規則，3 次取平均 | 越低越好 | 0.15 |

> 10/26 以前每個指標跟寫死的常模比（例如整體正確率 0.80／0.10），數字沒有實際資料依據，已移除。

> 另外會算「切換成本正確率」和「反應時間變異（rt_cv）」，**只供參考，不參與計分**。

### 5-2. 計算流程

```
① 算出 4 個原始指標
② 每個指標跟自己過去場次的原始指標（result.raw_metrics）比：
   z = (本場 − 歷史平均) ÷ 歷史標準差，越低越好的指標反向
③ 每個 z 先限制在 [−2, +2]
④ 加權 z = Σ(z × 權重) ÷ Σ(有用到的權重)
⑤ 分數 = round(50 + 25 × 加權 z)          → 1～100
```

- 程式：`calculate_executive_function_z_score`（②～④）、`calculate_cognitive_flexibility_score`（整份結果）
- 歷史由 `views.py` 用 `session_service.list_previous_results` 取出後傳入，`services.py` 仍不碰資料庫
- 加權 z 四捨五入到小數 3 位，存入 `result.z_score`（給儀表板用）
- **冷啟動**：自己不滿 3 場借全體使用者；全體也不夠 → `z_score`、`cognitive_flexibility_score` 為 `null`，結算 API 的 `current_score`、`encouragement_tier` 也是 `null`；`highest_score`、`recent_scores` 會跳過 `null` 的場次

### 5-3. 資料不足的處理

**單一指標不夠 → 跳過，權重按比例分給其他項**

- **切換成本 RT**：repeat 題、switch 題都要**各自答對 3 題以上**才計算
- 某個指標的歷史不足（例如舊場次沒有這個值）也一樣跳過
- 跳過時分子、分母都不算這一項，例如：

```
加權和 = 0.40 × (−0.5) + 0.25 × (−0.667) + 0.15 × (−0.625) = −0.4605
權重和 = 0.40 + 0.25 + 0.15 = 0.80          ← 沒有加 0.20
加權 z = −0.4605 ÷ 0.80 ≈ −0.576 → 分數 = round(50 + 25 × −0.576) ≈ 36
```

**整場不夠 → 不給分，回傳 HTTP 400**

| 錯誤代碼 | 情況 |
|---|---|
| `NO_SWITCH_TRIALS` | 整場沒有 switch 題 |
| `NO_REPEAT_TRIALS` | 整場沒有 repeat 題 |
| `INSUFFICIENT_QUESTION_COUNT` | 題數少於 28 題 |

### 5-4. 已拿掉的指標：持續性錯誤率

- 第一版（9/14）權重最高（0.35），9/30 拿掉（commit `9df194a`）
- 原因：籃子會跟著規則一起換，長者選不到「舊規則的籃子」，前端永遠判斷不出持續性錯誤，這一項永遠拿到很好的 z（模擬「28 題只答對 4 題」平均還有 76.6 分）
- 前端最新分支 `fix/pre-meeting-1006`（10/8）這個問題**仍然存在**
- 要加回來需要改玩法（例如固定籃子），待團隊討論

## 6. 冰箱檢查 fridge_check

雷達圖維度：**視覺空間**

### 6-1. 原始總分 `final_score`

程式：`games/fridge_check/services.py` 的 `calculate_final_result`

```
正確率   = 答對題數 ÷ 10 × 100                （重試後答對也算）
速度分   = Σ 每題答對時的速度分                （最高 100）
難度加分 = 中階答對數 × 0.5 + 高階答對數 × 1.0
跳題扣分 = 跳題數 × 2                          （同一題錯 3 次就跳題）

final_score = 正確率 × 0.7 + 速度分 × 0.3 + 難度加分 − 跳題扣分
```

| 答對時的反應時間 | 速度分 |
|---|---|
| ≤ 3 秒 | 10 |
| ≤ 6 秒 | 8 |
| ≤ 10 秒 | 5 |
| > 10 秒 | 3 |

- 只限制 ≥ 0，不設上限：最高 **105.5**（70 + 30 + 中階 3 題 × 0.5 + 高階 4 題 × 1.0）

### 6-2. z-score

```
raw_score      = 正確率 × 0.7 + 速度分 × 0.3     （不含難度加分、跳題扣分）
z              = (raw_score − 自己過去場次 raw_score 平均) ÷ 標準差
z 限制在 [−2, +2]
standard_score = round(50 + 25 × z)          → 1～100
```

- **用 `raw_score` 而不是 `final_score` 算 z**：難度加分、跳題扣分是給長者的遊戲回饋，不混進能力指標
- 例：過去場次平均 70、標準差 10，這場 raw_score 80.3 → z = 1.03 → standard_score = **76**
- 冷啟動：自己不滿 3 場借全體使用者；全體也不夠 → `z_score`、`standard_score` 為 `null`
- 程式：`calculate_visual_spatial_z_score`；歷史由 `session_service.list_previous_results` 提供
- 結算 API 回傳 `raw_score`、`z_score`、`standard_score`；歷史 API 的 `score` 是 `final_score`

## 7. 市場買菜 market_shopping

雷達圖維度：**數學**

### 7-1. 原始分數

程式：`games/market_shopping/services.py` 的 `calculate_final_result`

```
total_correct           = 最後有完成的題數（含重試後完成）
first_try_correct_count = 選菜和找零都一次就答對的題數
accuracy                = first_try_correct_count ÷ 10 × 100
速度分                  = Σ 每一步答對時的速度分（選菜、找零各算一次，最高 100）
```

| 答對時的反應時間 | 每一步速度分 |
|---|---|
| ≤ 3 秒 | 5.0 |
| ≤ 6 秒 | 4.0 |
| ≤ 10 秒 | 2.5 |
| > 10 秒 | 1.5 |

> 一題兩步（選菜、找零）滿分 10 分，10 題滿分 100 分；答錯不給速度分。

### 7-2. z-score

```
raw_score      = accuracy × 0.7 + 速度分 × 0.3   （沒有反應時間資料時 raw_score = accuracy）
z              = (raw_score − 自己過去場次 raw_score 平均) ÷ 標準差
z 限制在 [−2, +2]
standard_score = round(50 + 25 × z)          → 1～100
```

- 例：過去場次平均 70、標準差 10，這場一次答對 8 題、速度分 80 → raw_score = 56 + 24 = 80 → z = 1.0 → standard_score = **75**
- 冷啟動：同冰箱檢查；程式：`calculate_math_z_score`
- 加入速度分後，分數不再只有 5 種值
- 結算 API 回傳 `raw_score`、`z_score`、`standard_score`；歷史 API 的 `score` 是 `raw_score`

## 8. 共用工具 `games/zscore.py`

五款遊戲與聲影日記共用（10/26 起）。只做計算，不碰資料庫。各遊戲把指標規則寫成
`METRIC_RULES = {指標: (權重, 是否越低越好)}`。

| 函式 | 用途 |
|---|---|
| `compute_baseline(values)` | 算歷史的（平均, 標準差）；不滿 3 場或標準差為 0 時回傳 `None` |
| `choose_baseline(personal, population)` | 冷啟動：個人算得出基準就用個人的，否則用全體使用者的 |
| `to_z_score(value, baseline, lower_is_better)` | 算 z，越低越好的指標乘 −1，結果限制在 ±2（`Z_SCORE_CLAMP`） |
| `weighted_average(scores_and_weights)` | 加權平均，跳過 `None`，剩下的權重按比例放大 |
| `metric_z_scores(current, personal, population, metric_rules)` | 每個指標各自跟歷史比，回傳 `{指標: z 或 None}` |
| `weighted_metric_z_score(z_by_metric, metric_rules)` | 依 `METRIC_RULES` 的權重加權；全部無資料回傳 `None` |
| `calculate_dimension_z_score(...)` | 有分階段的遊戲（菜市場找路、煮菜過程）：每階段用 `metric_z_scores`，再跨階段加權 |
| `z_score_to_display_score(z)` | z → 1～100 分（50 + 25z），`None` 回傳 `None` |

歷史資料由 `games/session_service.py` 提供，**只取比這場更早結束的場次**，所以 dashboard 不管什麼時候算，同一場的結果都一樣：

| 函式 | 給誰用 |
|---|---|
| `list_previous_step_records` | 菜市場找路、煮菜過程（逐題作答紀錄） |
| `list_previous_results` | 整理菜籃、冰箱檢查、市場買菜（結算結果 `result`） |

聲影日記的歷史是更早建立的有效日記，見 11-4。

### 冷啟動（每個階段、每個指標分開判斷）

| 情況 | 用誰當比較基準 |
|---|---|
| 個人同一階段歷史 ≥ 3 場 | 自己的歷史 |
| 個人 < 3 場 | 全體使用者在該階段的歷史（含自己） |
| 全體也 < 3 場 | 這個指標記為無資料 |

### 特殊情況

| 情況 | 處理方式 |
|---|---|
| 歷史每場數值都一樣（標準差 = 0） | 改用全體使用者；全體也是 0 就記為無資料 |
| 某個指標或階段無資料 | 跳過，剩下的權重按比例放大 |
| 全部無資料 | 回傳 `None`，前端顯示「資料不足」，不顯示 0 或假分數 |

## 11. 儀表板與週報表

程式：`dashboard/services.py`（儀表板）、`dashboard/weekly_report.py`（週報表）、`dashboard/diary_zscore.py`（聲影日記語言 z）、`ai_service/weekly_summary.py`（週報一句話總結）

兩支 API 都**只讀資料、不寫入任何資料表**，每次請求當下計算：遊戲從 `GameSession.result.z_score`，聲影日記從 `DiaryAnalysis` 的小分數現算（見 11-4）。

### 11-1. 遊戲與維度對照

| 順序 | 維度 | source | 資料 |
|---|---|---|---|
| 1 | 注意力 | `market_route` | 菜市場找路 z |
| 2 | 工作記憶 | `memory_recall` | 煮菜過程 z |
| 3 | 執行功能 | `market_sort` | 整理菜籃 z |
| 4 | 視覺空間 | `fridge_check` | 冰箱檢查 z |
| 5 | 數學 | `market_shopping` | 市場買菜 z |
| 6 | 語言 | `diary` | 聲影日記語言 z（見 11-4） |

### 11-2. 儀表板 `GET /api/dashboard/`（雷達圖）

```
各維度 z_score = 近 7 天結束場次的 z 平均（四捨五入到小數 3 位，範圍 ±2）
```

- **解鎖門檻**：五款遊戲**各自累計**至少 3 場「有 z_score」的場次才顯示，否則回傳 `INSUFFICIENT_DATA` 和各遊戲進度
- 解鎖後近 7 天沒玩的遊戲，該軸 `z_score` 為 `null`
- **語言軸**：近 7 天有效日記的語言 z 平均，`session_count` 是日記篇數；近 7 天沒有有效日記時為 `null`
- 日記**不列入解鎖門檻**，沒寫日記也能解鎖

### 11-3. 週報表 `GET /api/dashboard/weekly-report/`

看「上一個完整的週」（週一～週日），比較對象是再前一週。不設解鎖門檻。

| 項目 | 算法 |
|---|---|
| 有活動的日子 | 那天有開始玩遊戲或寫日記（沒有登入紀錄表，用這個代替） |
| 能力週分數 | 那週的 z 平均（遊戲依結束時間、日記依建立時間）→ `round(50 + 25 × z)`，限制 1～100 |
| 個人最佳 | 到報告週為止，每週分數的最高值 |
| 趨勢 | 本週 − 上週 ≥ +3 → `up`、≤ −3 → `practice`（多練習）、其他 → `steady` |
| 整體表現 | 有分數的能力（含語言）取平均 |
| 一句話總結 | 只把正向事實交給 AI；AI 失敗、超過 40 字或出現禁用詞 → 固定句型 |

> 週報給長者看，**不出現 z 分數等專有名詞、不出現負面字眼**，回傳的都是 1～100 分數和趨勢代碼。

### 11-4. 聲影日記語言 z

程式：`dashboard/diary_zscore.py` 的 `calculate_language_z_score`、`dashboard/services.py` 的 `diary_z_scores`。**不改 `diary/analysis.py`**，只讀它算好、存在 `DiaryAnalysis` 的 5 個小分數。

比照遊戲：每篇日記的每個小分數跟**更早建立的有效日記**比、每個指標限制 ±2、再加權。

```
① 一篇日記的 5 個小分數（每個 0～4 分）
② 每個小分數跟自己更早的有效日記比：z = (小分數 − 歷史平均) ÷ 歷史標準差，限制在 [−2, +2]
③ 語言 z = Σ(z × 權重)
④ 儀表板：近 7 天各篇語言 z 的平均；週報：每週平均 → 50 + 25z
```

| 指標 | 權重 |
|---|---|
| 流暢度 `fluency_score` | 0.20 |
| 資訊量 `information_score` | 0.20 |
| 句子組織 `sentence_score` | 0.20 |
| 命名 `naming_score` | 0.15 |
| 語意 `semantic_score` | 0.25 |

- **權重**沿用 `analysis.py` 的 `communication_score`（雲奇 9/22 訂的，來源待確認）；測試會檢查兩邊一致
- **冷啟動**：自己更早的日記不滿 3 篇 → 借全體使用者更早的日記；全體也不夠 → 這篇沒有語言 z，不列入平均
- **只比更早的**：同一時間建立的日記不互相當歷史；7 天以前的日記雖然不算進儀表板平均，仍然會當歷史
- **無效日記**（`is_valid = False`，錄音太短或疑似辨識錯誤）沒有小分數，不算結果也不當歷史
- 一次查出所有有效日記、依建立時間掃過去，不會每篇各查一次資料庫；z 隨時都能現算，**不用存進資料表**
- 範例：更早 3 篇的小分數都是 1、2、3（平均 2、標準差 1），這篇 4、2.67、3、2.8、3.33 → z 為 +2、+0.67、+1、+0.8、+1.33 → 語言 z ≈ 1.19
- 10/26 以前用寫死的常模（平均 2、標準差 1）
